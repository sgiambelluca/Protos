Ejercicio 1 — Proxy Squid + Basic auth

El hackerspace sólo lo conoce el proxy: su nombre no está en tu resolver, así que curl directo no resuelve. El que resuelve el nombre es el proxy — igual que socks5h:// (con la h) frente a socks5:// (resolvés vos).

# directo NO resuelve:
curl http://hackerspace.protos.foo:8090/          # Could not resolve host

# por el proxy SÍ (el proxy resuelve y trae la página):
curl -x http://ej1.protos.foo:3126 http://hackerspace.protos.foo:8090/
#   -> credenciales de miembro (debsec / hackerspace) y el link /novedades/

# el tablón pide Basic auth -> se la pasás con -u:
curl -x http://ej1.protos.foo:3126 -u debsec:hackerspace \
     http://hackerspace.protos.foo:8090/novedades/
#   -> el último anuncio es la FLAG{...}
  • -x http://proxy:puerto = proxy HTTP: el pedido sale en forma absoluta (GET http://host/ HTTP/1.1).
  • -u user:pass manda Authorization: Basic base64(user:pass). Sin credenciales el server responde 401 con WWW-Authenticate: Basic.

Ejercicio 2 — Vhosts por Host + proxy reverso + SSH con passphrase

# 1) bajar la clave: el vhost se elige por el header Host (no por DNS)
curl http://127.0.0.1/sec/mykey -H "Host: google.com" -o mykey
head -1 mykey                 # -----BEGIN OPENSSH PRIVATE KEY-----

# 2) permisos estrictos (si no, ssh/ssh-keygen la rechazan)
chmod 600 mykey

# 3) la passphrase vive en el host interno, que sólo se alcanza por el proxy del :81
curl http://127.0.0.1:81/ -H "Host: secrethost"
#   -> "La passphrase ... es: clave-del-parcial"

# 4) entrar por SSH como pepito (poné la passphrase del paso 3 cuando la pida)
ssh -i mykey pepito@127.0.0.1
Trampas. El chmod 600 no es opcional: con permisos abiertos hasta ssh-keygen -y ignora la clave ("UNPROTECTED PRIVATE KEY FILE"). El vhost se elige por Host, no por IP ni DNS. El :81 reenvía a 127.0.0.1:8000, que no es accesible directo desde afuera: por eso la passphrase está "escondida".

b) Leer por POP3 y mandar uno a mano

# leer (:110)
nc -C 127.0.0.1 110
USER debsec
PASS debsec
STAT            # cuántos mensajes
LIST            # número + tamaño
RETR 1          # muestra el mail (el cuerpo viene en base64)
QUIT
# decodificar:   echo '<base64>' | base64 -d

# mandar uno (:25) — con nc hace falta -C (CRLF)
nc -C 127.0.0.1 25
EHLO pdc.lab
MAIL FROM:<debsec@pdc.lab>
RCPT TO:<debsec@pdc.lab>
DATA
From: DebSec <debsec@pdc.lab>
To: <debsec@pdc.lab>
Subject: DebSec report
Content-Type: text/plain; charset=UTF-8
Content-Transfer-Encoding: base64

b2ssIHRvZG8gZW4gb3JkZW4=
.
QUIT
Trampas. nc -C termina las líneas con CRLF (lo que pide SMTP/POP3). Los mails sin leer están en ~/Maildir/new; al hacer login POP3 pasan a ~/Maildir/cur. EHLO/HELO saludan; HELLO no existe.

Ejercicio 4 — Reconstruir la zona DNS desde el PCAP

# 1) bajar la captura y abrirla
curl -O http://127.0.0.1:8008/backup.pcap
wireshark backup.pcap                 # la GUI no tiene el perfil AppArmor que molesta a tshark
# (por consola:  tshark -r - < backup.pcap -Y dns )

# 2) de cada reply AUTORITATIVA (flag aa) saco un registro con su TTL.
#    El SOA aparece también en una respuesta NEGATIVA (NXDOMAIN), en la sección Authority.

Zona reconstruida (/etc/bind/zones/db.cachito.parcial):

$TTL 3600
$ORIGIN cachito.parcial.
@   IN  SOA ns1.cachito.parcial. admin.cachito.parcial. (
            2018010101 ; serial original (2018010100) + 1 por el TXT nuevo
            3600 1800 1209600 300 )
@           IN  NS    ns1.cachito.parcial.
ns1         IN  A     192.168.0.238
@           IN  A     192.168.0.238
www         IN  CNAME @
@           IN  MX 10 mail.cachito.parcial.
mail        IN  A     192.168.0.238
@       864000 IN TXT "cachito meme: no toques la zona"
@              IN TXT "cachito tiene prohibido editar este archivo"
# declarar en /etc/bind/named.conf.local:
#   zone "cachito.parcial" { type master; file "/etc/bind/zones/db.cachito.parcial"; };
sudo named-checkconf
sudo named-checkzone cachito.parcial /etc/bind/zones/db.cachito.parcial
sudo rndc reload               # si la zona ya estaba declarada y sólo cambió el archivo
dig @127.0.0.1 cachito.parcial ANY +noall +answer    # tienen que venir con flag 'aa'
Trampas (las que más cuestan).
  • El TTL del TXT "meme" es 864000 (10 días), distinto del resto (3600): copialo tal cual sale de la captura, no asumas el $TTL.
  • Los dos TXT de @ son el mismo RRset (cachito.parcial/TXT) y un RRset tiene un solo TTL: BIND unifica ambos al del primero (864000) y avisa TTL set to prior TTL. Es correcto; por eso no tiene sentido ponerle 3600 al TXT nuevo.
  • www es un CNAME a @, no un A.
  • El SOA sale de la respuesta negativa (NXDOMAIN). El serial sube en 1 porque agregaste un registro.
  • rndc reconfig carga zonas nuevas; si cambiás el archivo de una zona ya declarada, usá rndc reload.
