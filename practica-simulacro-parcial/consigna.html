Ejercicio 1 proxy + HTTP

Pertenecés a la organización de hackers DebSec, cuyo objetivo es hackear a Bloom, una organización que recopila información personal de los ciudadanos mediante el sistema de trackeo ct 2.0.

Querés ver qué novedades hay en el grupo. Empezá por el sitio de DebSec:

curl http://ej1.protos.foo/

Esa página te va a decir cómo seguir (spoiler: el hackerspace se escondió detrás de un proxy). Seguí las pistas de cada paso hasta leer el último anuncio del tablón, que es sólo para miembros.

Ejercicio 2 nginx + SSH

El host tiene un servidor nginx con los siguientes sitios habilitados:

server {
    listen 80;
    root /var/www;
    index index.html;
    server_name google.com;
    location / { try_files $uri $uri/ =404; }
}
server {
    listen 81;
    server_name secrethost;
    location / { proxy_pass http://127.0.0.1:8000/; }
}

Asimismo, este host tiene un servidor OpenSSH que sólo acepta el login del usuario pepito con clave privada. Sabemos que dicha clave privada está guardada en /sec/mykey. Por desgracia, nos informan que pepito le puso una contraseña (passphrase) a la clave.

Extraé la clave, averiguá la passphrase y entrá por SSH como pepito. Empezá mirando la portada de ese sitio (acordate de elegir el vhost con el header Host):

curl http://127.0.0.1/ -H "Host: google.com"

Cada paso te deja la pista del siguiente, hasta el ssh final.

Ejercicio 3 SMTP + POP3

a) Tu compañero de parcial está intentando mandar un mail por nc pero comete un par de errores al escribir el protocolo. Como no querés que recurse, marcale en su hoja los errores que encontrás:

ubuntu> nc 192.168.0.168
HELLO localhost
MAIL FROM: friend@pdc.lab
MAIL TO: <you>
DATA
Subject: Hola

¿Cómo estás?
QUIT

b) Al salir del examen, tu compañero asegura que el mensaje le debió haber llegado. Confirmalo (o refutalo) revisando la casilla por POP3.

En la VM tenés una casilla: POP3 usuario debsec, clave debsec, dominio pdc.lab. Empezá leyendo el correo por POP3 (nc -C 127.0.0.1 110): hay un mail que te dice el próximo paso. Seguí esa pista, mandá tu reporte por SMTP y confirmá por POP3 que entró.

Ejercicio 4 DNS / bind9

Cachito, un junior de tu empresa, borró accidentalmente todos los archivos de configuración de la zona DNS, y el cronjob que ejecutaba los backups no se corre desde 2018. Afortunadamente, quedó guardada una captura PCAP con queries y replies del namemaster, en un server HTTP. Mirá qué hay y seguí la pista:

curl http://127.0.0.1:8008/          # te dice qué bajar y qué hacer
curl -O http://127.0.0.1:8008/backup.pcap

Restaurá la configuración original de la zona cachito.parcial con bind9, y agregá un record TXT que diga cachito tiene prohibido editar este archivo.

Aclaración del profe: si ya tenés un DNS configurado con bind, es más fácil; si no, es “picante”.
